# 原生 PSO 元数据检查

渲染管线种子保存的是原生 C 结构的完整字节表示。`nvn_pso_wire.h` 是渲染器和工具共同使用的结构及十六进制编解码定义；`nvn_pso_skey.h` 保留从实际着色器对象生成种子的接口。结构定义与原有字节格式一致。

`pso_codec.c` 是独立的 CPU 工具。它通过真实的 `sizeof`、`_Alignof` 和 `offsetof` 输出本次编译的结构布局，再按同一原生解析器检查输入。Python 的 `pso_native.inspect_keys` 接受调用者明确提供的工具及 SHA-256，在执行前后核对工具身份，检查完整的布局、顺序、数量和结束记录；它不使用硬编码的 Python 字节偏移。

## 支持范围

每个输入是一个 `R` 行中的十六进制载荷，不包含 `R` 标签。检查要求固定字符串正确终止并补零、键名符合基础或 BF 形式、顶点及可选片元阶段正确、三个序列化对象指针为空、布尔标记有效。普通管线的特化描述必须为空。合并或特化管线的专属描述保持不透明，并被标为排除项；工具不会清除其标记或把它重建成普通管线。键对应的实际着色器、格式枚举和 GPU 管线仍需由后续元数据及 Metal 检查认证。

工具使用 `merged=1`、`specialized=2`、`framebuffer_fetch=4` 三个位报告排除原因，可组合。调用者须保持原始行及其顺序，在验证完整键/阶段关系后执行配置过滤。未知记录、非法原生载荷或不完整工具输出是错误，不生成成功结果。

当前全部 198 个渲染种子通过原生结构检查，其中 148 个没有这三类排除标记。原有序列化测试、原生字段负例、Python 完整工具调用和故障注入、ASan/UBSan 通过；25 项既有布局事实与拆分后的定义一致。检查没有创建 Metal 设备或运行游戏。工具输出仅证明该工具的 CPU ABI，调用者还须冻结源码、头文件、编译器和工具身份，并与目标构建的 ABI 比较。

## 构建与检查

从仓库根目录构建，产物留在 `.tmp`：

```sh
mkdir -p .tmp/simulator-tools
xcrun --sdk macosx clang -std=c11 -Wall -Wextra -Werror \
  -I dm/gfx/nvn/include dm/ios/tools/simulator/pso_codec.c \
  -o .tmp/simulator-tools/pso_codec
make -C dm/gfx/tests pso-profile
python3 dm/ios/tests/test_pso_native.py
```

原生工具从标准输入读取载荷行，允许最后一行省略换行；空行、非十六进制字节、内嵌 NUL、错误长度及不支持的字段会以非零退出码报告。无载荷时输出完整布局和零条记录。Python 接口要求精确的工具身份，并传播原生错误和超时。

配置描述文件、真正重新生成的 C1、按配置过滤的 PSO 清单、构建及预热流程和用户管线缓存隔离仍由后续整合完成。CPU 结构布局检查不代表 Metal 原生参数布局或 GPU 管线兼容性，当前构建器与游戏启动检查仍保持原来的启用条件。
