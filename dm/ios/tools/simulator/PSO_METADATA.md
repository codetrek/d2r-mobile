# 模拟器源码配置元数据

`profile_metadata.py` 为已验证的基础着色器派生配置生成并重放检查元数据。结果仅证明源码和 CPU 原生序列化关系，`compiled`、`executed`、`renderer_qualified` 均为 `false`；不会启用构建器、绕过游戏检查或证明 Metal 管线可以运行。

## 输入与输出

输入必须明确提供原始 MSL 缓存、原始源码资格清单、已经生成的派生配置目录和原始元数据目录。生产与验证均调用 `shader_profile.validate_derived`，对照完整原始输入逐个重放转换及文件身份；映射表中的每个键、运行时阶段与原始及派生反射必须一致。阶段标签从当前渲染器的 `stage_of` 契约读取并绑定，不另行猜测外壳和域阶段的名称。元数据绑定该函数的精确函数体及标签，不把其他渲染器实现修改当作阶段变化；完整渲染器源码的冻结属于构建器责任。

输出只能是项目 `.tmp` 下的新目录，且精确包含四个普通文件：

| 文件 | 内容 |
|---|---|
| `shader_map.tsv` | 原始映射表的完整字节 |
| `c1_full.tsv` | 真实 `c1_guard.py` 对派生源码生成的内容和本次时间戳 |
| `pso_manifest.tsv` | 带配置、链、原生布局及来源身份头的有序支持记录 |
| `metadata-profile.json` | 封闭结构的来源、工具、输出身份、逐行决策及计数描述 |

生产先冻结工具和输入，完成原生检查、C1 与源码重放。最后一次完整重放及临时描述文件写入完成后，再核对原始/派生文件闭包、原生工具闭包、当前输入和生产器、精确输出集合与各文件哈希，以及临时描述文件内容，然后原子发布描述文件。生产和验证共用同一最终输入核对函数：验证入口在最后一次完整重放之后、返回之前也重新核对原始/派生文件及工具/来源闭包，并在其后检查输出集合与身份。晚于最后一次重放发生的输出篡改、额外文件或输入/生产器/原生闭包漂移会阻止发布或验证成功。输入与输出、工作目录不得重叠或经过符号链接。额外或缺失输出文件、重复 JSON 字段、未知结构字段、身份漂移、错误顺序或计数都不能成为有效结果。

`provenance_id` 由逻辑来源计算，种子头引用该身份；描述文件再绑定种子字节，避免相互引用的哈希循环。完整描述文件的 SHA-256 是调用者保存和后续验证的入口身份，将来用户管线缓存还须结合它、配置、链及原生布局隔离。

## 原生键与有序过滤

`nvn_pso_wire.h` 是渲染器与工具共用的原生结构及十六进制编解码定义。`nvn_pso_skey.h` 保留从实际着色器对象生成种子的接口；结构及字节格式与拆分前一致。`pso_codec.c` 检查固定字符串、基础或 BF 键、顶点及可选片元阶段、空对象指针与布尔标记。普通管线的特化描述必须为空；合并或特化管线的专属描述保持不透明，分类后排除，不重建成普通管线。

元数据生产器检查每个原始 S/R/C 记录的完整形状和键阶段关系，保留所有支持记录的原始行体字节及顺序。BF 必须对应原始资格清单中真实声明的片元变体，随后排除；合并和特化记录也排除，并记录全部原因。明确的 `C` 加单个制表符空记录属于已有不可执行条目，按 `empty_compute` 排除；缺列、其他错误键、未知标签和损坏原生载荷仍是错误。

每条决策记录原始行号、标签、行体 SHA-256、保留或排除及原因列表。描述文件绑定原始与保留计数、排除特征计数和有序输出行体哈希。当前真实输入包含 6,927 个唯一映射键、392 条种子；支持的 341 条为 181 个 S、12 个 C 和 148 个 R。其余为 44 条合并、6 条合并且特化，以及一个空 C。过滤保持原始语义，不改变附件映射或合并标记。

## 真实工具身份与重放边界

`pso_toolchain.NativeCodec` 将真实生产 C 和头文件闭包复制到只读自有输入，用明确的 Apple clang 编译 ARM64 CPU 工具；记录编译器、版本、参数、实际 SDK/头文件依赖及输出身份，并在运行前后再次核对。原生输出通过 `pso_native.inspect_keys` 检查完整顺序、数量和结束记录。原生 `sizeof`、`_Alignof`、`offsetof` 与主机和模拟器目标的编译器布局相互对照，Python 不重建固定字节偏移。

描述文件分别绑定持久的源码、编译器、布局和语义关系，以及本次真实产生的工具二进制身份。后续验证重新构建自有工具，比较相同契约及实际语义输出；不会声称历史 Mach-O 二进制必然逐字节重现。链接 UUID、构建路径与历史输出身份不被伪装为可重复二进制证明。Python 解释器身份和版本也属于来源契约。

C1 使用同一个真实生产器分别处理原始与派生 `.metal`；新生成的原始行与提供的原始 C1 行、派生行必须完全一致且排序、唯一、属于配置。输出保存生产器真实生成的派生链头和时间戳。验证重新运行生产器，比较正确的头部语法及有序行；新的时间戳可以不同，历史文件则必须匹配调用者保存的描述文件及文件身份。不会改写旧头或宣称时间戳字节可重现。

## API 与检查

需要 macOS、Xcode 和 Python 3.10 以上。部分 macOS 的 `/usr/bin/python3` 仍为 3.9，请明确选择符合要求的解释器。所有输出及临时工具留在项目 `.tmp`。

```sh
make -C dm/gfx/tests pso-profile
make -C dm/ios/tests profile-metadata PYTHON=python3.13
python3.13 dm/ios/tests/test_pso_native.py
```

将 `dm/ios/tools/simulator` 加入 Python 模块路径后调用：

```python
from profile_metadata import produce_metadata, validate_metadata
from pso_toolchain import identity

result = produce_metadata(cache, qualification, derived, original_metadata,
                          destination, work=production_work)
descriptor_sha256 = identity(destination / "metadata-profile.json")["sha256"]
validated = validate_metadata(destination, cache, qualification, derived,
                              original_metadata,
                              expected_descriptor_sha256=descriptor_sha256,
                              work=replay_work)
```

`destination`、`production_work` 和 `replay_work` 都由调用者提供；每个工作目录须为新的独立 `.tmp` 子目录。验证描述文件需要先前保存的明确 SHA-256，不能以读取待检文件后自动信任它替代准入身份。错误、工具失败和超时会传递给调用者。

检查使用按原生成员构造的独立夹具，覆盖交错未排序 S/R/C、可选空片元、BF、不可重建的排除描述、坏字段及阶段、损坏输入、空 C、输出及来源漂移、封闭结构、布局和计数变异、符号链接与重叠路径；完整生产与重放还对照手写的预期支持子序列。真实 C1、6,927 键及当前种子另有私有 CPU 回执。

完整元数据已可独立生产和验证。构建暂存、预热共享编译契约、用户管线缓存隔离、Metal 原生参数布局、真实 PSO 编译与游戏世界仍须各自整合及运行证明；这些工作完成前，源码配置和游戏启动检查保持原有启用条件。
