# 共享库编译与严格准备

`dm_metal_library.h/.m` 统一翻译着色器的源码/二进制装载和编译选项。渲染器 `lib_from_file`、准备流程和独立诊断都经由同一入口。源码使用 UTF-8 和 `newLibraryWithSource:options:error:`，选项为原有的 `nil` 默认值；二进制继续通过关闭文件描述符后的 mmap/dispatch-data 使用 `newLibraryWithData:error:`。普通渲染器同步调用方式保持，有限时准备在自有工作队列调用同一构造方法。正数时限从调用入口开始，文件读取、UTF-8 解码、排队和结果接收共用同一个 systemUptime 绝对截止时间；每次派发及工作者真正调用构造方法前再次核对，迟到结果不能写入成功票据。渲染器的零时限保留同步语义。超时不会取消系统编译，但停止新请求、忽略迟到结果，保留失败状态；外部诊断控制器仍须设置整个进程期限。

构建器将共享编译器 `.h/.m` 的真实源码身份写入 `DM_METAL_LIBRARY_CONTRACT_SHA256`。契约还记录实际 Clang、载入映像 UUID、API 和选项；完成回执结合配置/元数据/链身份、完整 OS build、真实设备及该编译契约隔离。未生成源码身份的普通物理构建明确记录该字段为空，仍按实际映像和语义契约区分；严格派生配置必须具有真实的生成身份。

## 派生配置准备

`DmProfileLibraryPlan` 读取固定包内描述文件和编译时钉住的元数据 SHA-256，不搜索任意链来决定配置。完整配置文件身份由钉住的元数据关联验证；映射/C1/过滤 PSO、全部基础 JSON 与源码库必须逐字节匹配描述。链目录精确包含每个基础键的一对文件，不允许 BF、额外/缺失文件或符号链接。反射键、阶段、入口名及 Metal 入口类型相互绑定。JSON 的重复字段、结构或身份错误会明确失败。

配置清单验证在后台线程执行，避免阻塞窗口。单次清单验证限制为 2 分钟，单份源码最多 64 MiB、源码总量最多 2 GiB、最多 32,768 个键；当前配置为 6,927 个。每份库和函数在各自自动释放池内处理，不创建 `NvShader`、C1 缓冲或原生参数编码器。

派生流程使用一个活动工作者；每批最多 64 个键，批次上限 2 分钟，每键构造库及取入口合计上限 0.5 分钟，运行总上限 30 分钟。每键在首个检查点之前捕获键/批次/整段三者中最早的绝对截止时间，输入复核、读取、库及入口处理、后续哈希和结果检查点共用该期限。第一处错误、期限或持久化失败会停止新请求，其余键明确列为未尝试。每个键记录源与反射身份、原阶段、入口及 `vertex`/`fragment`/`kernel` 类型；HS 按 `kernel`、DS 按 `vertex` 检查，仅说明翻译后的函数类型，不证明曲面细分渲染。

开始时写完整预期身份清单，每键在编译库与取入口之前写紧凑检查点，再写完成数量和失败信息。所有检查点保持 complete=false。最终回执包含完整预期/成功/失败/未尝试身份；只有最终检查点写入、完整输入再次核对及最后一个键/批次/整段截止检查均通过后，才向调用者返回 complete=true。慢检查点或慢复核不能产生已接受的成功回执；失败回执仍可在整段期限内保留。紧凑进度绑定预期清单哈希和数量，不反复重写数千条完整成功记录。回执固定声明 `library_compilation_only=true`，原生布局、PSO、渲染器及曲面细分渲染资格均为 false。

完成记号是受完整作用域和清单约束的 JSON，不能使用普通 `ok` 字符串。损坏的已有回执会阻止继续。派生配置即使库准备成功，也保持原应用准入待定：窗口说明图形验证尚未完成，不调用进入游戏的完成回调。主调用点使用空闲/等待/就绪状态，等待或失败后再次切回前台不会绕过准备；只有允许的成功回调或确实无需准备时才能释放此门。

普通物理/原始源码模式保留原有二进制无需准备的路径、源码缓存和 1–6 个有界编译工作者，使用同一 nil-options 编译入口。其源码准备也使用作用域 JSON、有限批次/总期限和成功/失败记录；错误不会再调用继续回调。此模式的现有游戏启动和渲染策略保持。

## 独立 host-only 案例

提交并独立审查后才可以构建/运行新产物。该案例单独通过 `-mode gpu` 和 `DM_GPU_PROBE_CASE=profile-libraries` 选择。它先验证明确的派生配置，然后创建设备并运行同一库/入口检查；不创建命令队列、不提交 GPU 命令、不运行 Guest、不建立 PSO 或原生参数布局。此长案例单独选择，`all` 保留现有较小 primitive 案例范围。

程序按完整/部分 JSON 写到自己的 Documents 报告，外部控制器应覆盖启动、2 分钟清单与 30 分钟编译运行，例如使用 35 分钟整个进程期限并持续核对进度；失败保持原始检查点和错误键，不自动把部分结果变成通过。旧的 app13 不包含本次编译器或这个新案例，不能用旧产物冒充本次运行。

由已提交 `71850f1` 构建的新 ARM64/platform7 诊断产物在 MTLSimDevice 上完成了全部 6,927 个配置键的实际 Metal 库及命名入口编译：4,559 个片元、2,344 个顶点、22 个计算及两个 HS/DS 声明入口类型。预期与成功身份逐项完全一致，失败和未尝试均为零，使用共享 nil-options 契约及 `810ecdb8…` 辅助函数身份。限时运行耗时 757.87 秒，前后全部 14,080 个安装文件一致，进程无崩溃并已停止，使用标记已释放。没有创建命令队列、提交 GPU 工作或运行 Guest；原生参数布局、PSO、渲染、曲面细分渲染、世界和存档资格仍分别待验证。 全库编译完成仍不代表冷启动前的完整安全渲染准备已完成，渲染配置和游戏能力检查保持未启用。
